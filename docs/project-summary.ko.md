# 로컬 LLM 실행 계층의 실패 진단과 변경 영향 검증

**논문:** 「8B LLM의 도구 사용 실패 분석: 형식 준수, 행동 선택 및 실행 종료」

## 해결하려던 문제

도구를 사용하는 LLM의 최종 오답만으로는 출력 파싱 실패, 잘못된 행동 선택, 호출 한도 내 응답 미제출을 구분하기 어려웠습니다. 로컬 8B 모델의 실행 과정을 세 관찰 지점으로 나누고, 특정 형식 오류를 완화한 조건에서 종료 상태와 정답 여부가 어떻게 달라지는지 분석했습니다.

## 담당 업무

연구를 직접 수행하며 기존 모델과 llama.cpp를 활용한 반복 평가, 실패 유형 분류, 진단 조건 비교와 결과 해석을 담당했습니다. When2Call 40문항을 각 8회 평가해 형식 준수와 행동 선택을 구분했고, Loc-Bench Security에서는 저장소를 탐색해 수정 대상 파일·함수를 찾는 과제로 반복 실행의 종료 상태를 분석했습니다.

## 핵심 분석과 대표 사례

실패 출력에서 관찰한 숫자 리터럴 뒤의 불필요한 큰따옴표 오류를 대상으로, 논문에서 정의한 parser-relaxed 사후 진단 조건을 strict JSON 조건과 비교했습니다. Granite의 공통 28문항을 각 8회 평가하고 도구 호출 한도를 8회로 둔 결과를 조건별 전체 224회 기준으로 비교했습니다.

| 관찰 지표 | strict JSON | parser-relaxed JSON |
| --- | --- | --- |
| 형식 중단 | 194/224회(86.6%) | 116/224회(51.8%) |
| 호출 한도 소진 | 24/224회(10.7%) | 87/224회(38.8%) |
| 최종 응답 제출 | 6/224회(2.7%) | 21/224회(9.4%) |
| 파일 일치 | 6/224회(2.7%) | 21/224회(9.4%) |
| 함수명 일치 | 4/224회(1.8%) | 17/224회(7.6%) |

형식 중단은 34.8%p 감소했지만 호출 한도 소진은 28.1%p 증가했고, 함수명 일치율의 증가는 5.8%p였습니다. 문항별로도 28문항 중 26문항에서 형식 중단 횟수가 감소하고 22문항에서 한도 소진 횟수가 증가해, 총점과 종료 상태를 함께 비교했습니다.

별도 native XML 조건에서는 같은 파일의 다른 행 범위를 읽고 추가 탐색을 요청하다 호출 한도로 종료된 사례를 살폈습니다. 재방문만으로 무한 반복이나 종료 로직 결함을 단정하지 않았고, 예산 부족과 종료 판단을 구분하려면 추가 평가가 필요하다고 해석했습니다.

## 결과 해석과 연구 경험

final은 최종 응답 제출이며 정답과 구분했고, function accuracy는 예측한 코드 위치의 파일 경로·함수명이 정답과 일치한 비율로 평가했습니다. 조건별 집계 차이를 개별 실행의 상태 전이로 단정하지 않았으며, 출력 규약과 도구 목록이 다른 native XML은 별도 비교로 다뤘습니다. 두 모델과 제한된 문항, 사후 진단 조건의 결과로 해석 범위를 한정했습니다.

연구 환경에서 기존 실행 흐름의 관찰 지점을 나누고, 제한된 변경 전후의 효과와 남은 문제를 지표로 설명했습니다. 이를 통해 소프트웨어 장애 분석, 수정 영향 검증, 검증 범위와 잔여 문제를 전달하는 기술 커뮤니케이션 경험을 쌓았습니다.

## 사용 기술

Python 기반 평가 코드, HTTP·JSON 방식의 llama.cpp 연동, JSON/JSONL 결과 처리와 정규식 기반 출력 해석을 활용했습니다. Granite 4.2-8B와 Ministral-8B-Instruct-2410을 Q5_K_M 양자화·RTX 5070 환경에서 평가하고, Granite native XML 도구 호출 조건을 함께 분석했습니다.
