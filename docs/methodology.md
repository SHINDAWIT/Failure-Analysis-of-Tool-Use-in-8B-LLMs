# 실험 방법과 결과 해석

실험 조건과 결과는 [논문](../CISC-W_2026_paper__196.pdf)의 표 2·3을 기준으로 정리했습니다.

## 공통 환경과 비교 조건

- 모델: Granite 4.2-8B, Ministral-8B-Instruct-2410
- 실행 환경: llama.cpp, Q5_K_M, iMatrix 미사용, RTX 5070, context 8192
- 반복: 각 문항 seed 0–7, 8회
- 기본 프로필: Granite thinking on·temperature 1.0, Ministral thinking off·temperature 0.7
- When2Call: 모델 호출 1회. Granite thinking off를 별도 조건으로 비교했습니다.
- Loc-Bench: 도구 호출 상한 8회. 상한 16회 등의 추가 조건은 평가하지 않았습니다.

프로필 차이가 있어 모델 간 수치를 순수한 모델 효과로 해석하지 않습니다. [공개용 설정 템플릿](../experiments/monkeys-passk-frontloop/spec/f0.json)은 기존 설정에서 가져온 값과 공개용 변경을 표시합니다.

## When2Call: 형식과 행동 선택

test/llm_judge 300문항에서 라벨별 UUID 정렬·라운드로빈으로 40문항을 선정했습니다. 호출 13문항, 추가 정보 요청 13문항, 해결 불가 판단 14문항이며 모델 출력 확인 전에 ID를 고정했다고 논문에 보고했습니다.

| 조건, 각 N=320 | 형식 준수 | 행동 정답 |
| --- | --- | --- |
| Granite thinking on | 308/320 (96.3%) | 199/320 (62.2%) |
| Granite thinking off | 311/320 (97.2%) | 208/320 (65.0%) |
| Ministral | 317/320 (99.1%) | 132/320 (41.3%) |

형식 유효와 정답 행동 일치를 모두 만족해야 행동 정답이며 형식 실패도 전체 분모에 포함합니다. 도구 인자와 실제 실행 결과가 모두 맞았다는 점수는 아닙니다. 정수 분자는 저장 요약의 문항별 정답 수를 합산한 값이고 비율은 논문 표기를 따릅니다.

Granite의 전체 행동 정확도 off−on 차이는 +2.81%p입니다. 문항별 8회 평균에 대한 짝지은 부트스트랩 10,000회로 구한 95% 구간 [−9.06, 15.31]%p는 0을 포함하므로, thinking을 끈 조건의 유의한 정확도 개선은 관찰되지 않았습니다. 신뢰구간은 논문에 보고된 값입니다.

## Loc-Bench Security: 종료와 정답

공식 Security 29문항 중 저장소 사용이 불가능했던 한 문항을 제외한 공통 28문항을 비교했습니다. 조건별 전체 시도 224회가 모든 표 비율의 분모입니다.

| 조건 | format_stop | tool_cap | final | 파일 일치 | 함수 일치 |
| --- | --- | --- | --- | --- | --- |
| Granite JSON strict | 194 | 24 | 6 | 6 | 4 |
| Granite JSON parser-relaxed | 116 | 87 | 21 | 21 | 17 |
| Granite native XML | 57 | 129 | 38 | 34 | 24 |
| Ministral JSON | 34 | 90 | 100 | 36 | 7 |

앞의 세 종료 상태는 상호 배타적이며 합계는 각 224회입니다. 파일·함수 일치는 별도 평가입니다. Function accuracy는 예측한 코드 위치의 파일 경로·함수명 일치입니다.

strict→relaxed 변화는 형식 중단 −78회/−34.8%p, 한도 소진 +63회/+28.1%p, final +15회/+6.7%p, 함수 일치 +13회/+5.8%p입니다. 조건별 합계 차이를 특정 개별 실행의 전이로 단정하지 않습니다.

### 진단 조건과 도구 차이

parser-relaxed는 실패 출력에서 관찰한 숫자 뒤 큰따옴표 오류를 대상으로 설정한 사후 진단입니다. 공개한 보존 코드의 repair_json_text()에는 후행 쉼표 제거도 포함돼 있습니다. 이 코드와 논문의 처리 범위 차이, 실행 당시 버전의 동일성은 미해결 사항입니다.

JSON 프롬프트에는 list_dir, read_file, grep, run(target="test")가 있고 native XML에는 앞의 세 탐색 도구가 제시됩니다. XML은 출력 규약·프롬프트 도구 목록이 다른 별도 비교입니다. 공통 스키마의 허용 집합과 실제 실행 지원은 또 구분해야 합니다. 보존 구현의 run은 테스트 미구성 응답을 반환합니다.

### 문항별 관찰과 남은 원인 구분

논문은 relaxed에서 strict 대비 형식 중단 횟수가 감소한 문항이 26/28개, 한도 소진 횟수가 증가한 문항이 22/28개라고 보고합니다. 8회 모두 final을 내지 못한 문항은 relaxed 21/28개, XML 18/28개입니다. 함수 정답을 한 번 이상 제출한 문항은 두 조건 모두 6/28개로, 정답 실행이 여러 문항에 균등하게 퍼진 결과는 아닙니다.

같은 파일의 다른 행 범위를 읽고 추가 탐색을 요청하다 호출 상한에 도달한 사례도 보고했습니다. 재방문은 다른 범위·검색어를 이용한 추가 탐색일 수 있어, 한도 소진만으로 무한 반복·종료 로직 결함이나 예산 부족 중 하나를 원인으로 확정하지 않습니다.

일부 중간 모델 출력과 도구 반환 본문이 보존되지 않았으며 호출 한도 증가 조건은 평가하지 않았습니다. 이 저장소에는 원시 원장을 배포하지 않으므로 공개 검산의 범위는 표 산술, 저장 요약의 집계 투영, 파일 해시와 코드 정적 열람입니다.
